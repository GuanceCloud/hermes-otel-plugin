# v0.1.10

Fix installation when Hermes uses a dedicated virtual environment and a separate data directory.

## Changes

- Use `HERMES_PYTHON` consistently for dependency installation, tag processing, and `config.yaml` updates. A system `python3` without PyYAML no longer blocks installation.
- Include PyYAML in runtime dependencies and report the selected interpreter when a dependency is missing. Missing interpreters fail before replacing plugin files.
- Merge YAML atomically while preserving unrelated configuration, existing permissions, and symlink targets.
- Align the package, plugin manifest, and runtime version to `0.1.10`; fail packaging on version drift, omit Python caches, and publish `SHA256SUMS` and an `install-release.sh` alias.

## Validation

Installer regressions use isolated temporary Hermes homes and virtual environments with an offline pip double. Coverage includes a host Python without YAML, runtime dependency bootstrap, custom directories with spaces, tags, unrelated settings, `--no-config`, missing runtime/YAML, invalid YAML, and symlinks. Unit tests and release packaging run in CI before publication. Customer-host installation and real Hermes/OTLP acceptance remain separate.

## Installation and recovery

Select the actual Hermes interpreter when code and data live separately:

```bash
export HERMES_HOME=/data/hermes-data
export HERMES_PYTHON=/opt/hermes-agent/.venv/bin/python
```

Use the matching release installer and either `latest` or `v0.1.10`. `--no-deps` requires PyYAML to already be installed in the selected interpreter when writing configuration. `--no-config` preserves configuration; rerun installation with configuration enabled to repair a previous failed config write.

This plugin release does not change `obs-agent-connector discover`. Custom-home discovery is addressed separately in connector PR #38; an older connector may still require `install hermes` explicitly.
