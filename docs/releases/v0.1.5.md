# v0.1.5

## Summary

`v0.1.5` normalizes skill telemetry fields, fixes the skill span hierarchy, and removes obsolete skill-source tags.

## What's Included

- Unified skill fields across `tool:skill_view` and `skill:*`:
  - `skill.name`
  - `skill.description`
  - `skill.path`
  - `skill_call_id`
  - `skill.source.type`
  - `skill.result_status`
  - `gen_ai.skill.*`
- Fixed the parent-child span chain to `llm -> tool -> skill`, so `skill:*` is now attached under the triggering `tool:skill_view` span instead of being emitted as a sibling span
- Standardized the tool-to-skill correlation field on `skill_call_id`
- Removed the old `skill_source` field from traces and metrics
- Added lightweight `SKILL.md` metadata extraction:
  - `skill.name` prefers the directory name that contains `SKILL.md`
  - `skill.description` prefers frontmatter `description`, then falls back to the first explanatory paragraph
  - `gen_ai.skill.version` prefers frontmatter `version`, then falls back to the nearest `package.json.version`
  - `skill.source.type` is normalized to `system`, `user`, or `workspace`
- Kept compatibility fields such as `skill_name` and `skill_description` while introducing the normalized `skill.*` and `gen_ai.skill.*` families
- Updated Chinese and English docs for trace fields, metric tags, and semantic field mapping

## Notes

- `skill:*` still represents the active execution window of a loaded skill, while `tool:skill_view` represents the load action itself.
- `gen_ai.skill.*` is currently emitted as a project extension field set. It follows the direction of community proposals, but it is not an official OpenTelemetry GenAI standard field family yet.
- Existing dashboards or queries that depend on `skill_name` can continue to work. New queries should prefer `skill.name` and `skill_call_id`.
- Metrics no longer emit `skill_source`, so any aggregation keyed on that tag needs to be updated.
