# v0.1.3

## Summary

`v0.1.3` fixes duplicate telemetry/resource tags, adds prompt-size diagnostics for trace analysis, and hardens the installer for Hermes runtimes that do not ship with `pip`.

## What's Included

- Stopped injecting `agent_runtime` into `resource_attributes`; telemetry-owned fields now stay on spans, metrics, and logs
- Filtered conflicting resource tag keys such as `session_id`, `platform`, `tool_name`, `request_model`, and all `request_*` / `usage_*` style telemetry fields
- Added session-cached system prompt diagnostics on `llm` spans:
  - `system_prompt_chars`
  - `system_prompt_bytes`
  - `system_prompt_hash`
- Added request-shape diagnostics on `llm` spans:
  - `request_message_count`
  - `request_tool_count`
  - `request_payload_item_count`
  - `request_payload_chars`
  - `request_payload_bytes`
- Added `request_user_prompt_estimated_tokens` on `hermes_request` and `agent_run` so user-visible prompt size can be separated from the full provider input
- Updated Chinese and English trace documentation to explain the new fields and their boundaries
- Updated the installer so it bootstraps `pip` with `ensurepip` before installing OTEL dependencies into the Hermes runtime

## Notes

- `request_user_prompt_estimated_tokens` is only attached to `hermes_request` and `agent_run`; it is intentionally not repeated on every `llm` span
- `system_prompt_*` comes from the local Hermes `state.db` session snapshot, so it is best used as a diagnostic proxy rather than a byte-for-byte guarantee of the backend's final effective prompt
- When estimating non-user prompt cost, use:
  - `(usage_input_tokens + usage_cache_read_input_tokens + usage_cache_write_input_tokens) - request_user_prompt_estimated_tokens`

## Validation

- `python3 -m unittest tests.test_trace_manager tests.test_config tests.test_plugin_register`
- Verified installer fallback with a temporary `python -m venv --without-pip` environment
